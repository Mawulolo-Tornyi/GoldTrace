======================================================================
0. CORE PURPOSE
======================================================================

GoldTrace is an intelligent environmental monitoring and early-warning
system designed to identify sensor patterns associated with possible
illegal mining activity near rivers.

The complete system must:

1. Collect data from remote ESP32 sensor nodes.
2. Monitor river turbidity.
3. Monitor machinery/engine sounds.
4. Monitor ground vibration.
5. Monitor water temperature.
6. Analyze changes between upstream and downstream nodes.
7. Use machine learning and deep learning.
8. Detect anomalies.
9. Fuse multiple sensor signals.
10. determine environmental/mining risk.
11. determine WHERE the suspicious activity is likely occurring.
12. display the suspected area on a map.
13. create a geospatial incident record.
14. generate HIGH and CRITICAL alerts.
15. automatically send qualifying alerts to configured authorized
    security/environmental agencies.
16. include the suspected location with every agency alert.
17. track whether alerts were delivered.
18. retry failed deliveries.
19. prevent duplicate/spam alerts.
20. expose all results through FastAPI for the GoldTrace frontend.

IMPORTANT:

GoldTrace must NOT treat a single abnormal sensor as legal proof of
illegal mining.

The system must NOT output:

"CONFIRMED ILLEGAL MINING"

Instead use:

POSSIBLE_MINING_ACTIVITY

HIGH_RISK_MINING_ACTIVITY

SUSPECTED_GALAMSEY_ACTIVITY

The purpose is to provide an actionable early-warning and investigation
location to authorized authorities.

======================================================================
3. MULTI-SENSOR ML PRINCIPLE
======================================================================

Never use:

high turbidity = mining

Never use:

machine sound = mining

Never use:

vibration = mining

A serious GoldTrace mining alert requires agreement between multiple
independent signals.

Important evidence includes:

- downstream turbidity increase
- machinery-like acoustic signature
- heavy machinery vibration
- persistence
- upstream/downstream difference
- anomaly score
- environmental model
- sensor health
- time synchronization
- model confidence

High rainfall with muddy water but no machinery should NOT generate a
CRITICAL galamsey alert.

Machinery sound without river disturbance should normally produce:

MACHINERY_ACTIVITY

rather than:

HIGH_RISK_MINING_ACTIVITY

======================================================================
46. ALERT POLICY
======================================================================

Default policy:

LOW
→ no agency alert

MEDIUM
→ dashboard/local event only

HIGH
→ notify GoldTrace monitoring/admin team
→ optionally notify agencies depending configuration

CRITICAL
→ automatically dispatch to all configured authorized emergency /
security/environmental recipients

But automatic CRITICAL dispatch is allowed only when:

1. sensor health is sufficient
2. event is persistent
3. more than one independent sensor supports the event
4. confidence exceeds configured threshold
5. localization exists
6. event is not SYSTEM_UNCERTAIN
7. event is not a duplicate
8. alert cooldown rules permit dispatch

Example configuration:

agency_alerts:
    enabled: true

    production_mode: false

    dispatch_threshold: CRITICAL

    minimum_confidence: 0.85

    minimum_agreeing_sensors: 3

    minimum_persistence_seconds: 30

    require_location: true

    cooldown_seconds: 300

    max_retries: 3

production_mode=false must prevent real external alerts during
development/testing.
